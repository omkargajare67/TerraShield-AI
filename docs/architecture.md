# TerraShield AI - Architecture Document (Phases 1 & 2 Hardened)

## 1. Overview
TerraShield AI is an AI-assisted geospatial decision-support platform designed to prioritize reforestation interventions for:
1. **Landslide Risk Mitigation:** Stabilizing unstable slopes through root-cohesion reinforcement.
2. **Air-Quality Buffers:** Filtering particulate matter via vegetative canopy placement.
3. **Urban Heat Mitigation:** Alleviating urban heat islands through strategic urban forestry.

The central prioritization metric across candidate planting sites is the **Leverage Score**:

$$L = \frac{\Delta R}{N}$$

Where:
- $\Delta R$: Modeled risk reduction achieved by the vegetative intervention.
- $N$: Number of trees required for the intervention footprint.

## 2. Intended Pilot Study Corridor vs. Synthetic Demonstration Basins

### Intended Project Pilot Study Region: Western Ghats Corridor
TerraShield AI is designed for real-world deployment in the **Western Ghats Mountain Corridor (India)**, a UNESCO World Heritage biodiversity hotspot experiencing severe monsoon-triggered shallow landslides and agricultural soil loss.
- **Pilot Region:** Western Ghats Corridor (Kerala, Tamil Nadu, Karnataka).
- **Target Geographic Bounds:** `9.20° N – 12.00° N`, `75.80° E – 77.50° E`.
- **Recommended Projected CRS:** `EPSG:32643 (WGS 84 / UTM Zone 43N)`.

### Three-Tier Data Provenance Model
To avoid confusion between test mocks and ground-truth observations, TerraShield AI strictly enforces three data categories:
1. **Tier 1 — Synthetic Test Fixtures (`data/sample/`):** Deterministic mock datasets (Cascade Foothills demo parcels, 10x10 synthetic DEM, synthetic Sentinel-2 Red/NIR bands) used exclusively for automated test verification and offline demonstration.
2. **Tier 2 — Real Environmental Observations (`data/raw/` or `data/uploads/`):** Genuine external inputs (NASA SRTM DEM, Sentinel-2 L2A tiles, ISRIC SoilGrids, WDPA reserves) uploaded or placed by users.
3. **Tier 3 — Derived Geospatial Products (`data/processed/` & `data/artifacts/`):** Continuous GeoTIFFs (Slope, Aspect, NDVI) and GeoJSON outputs generated by the verified engine.

## 4. GeoTIFF Metadata Compatibility & Engine Limitations

### Supported Metadata Formats
The raster inspection engine supports standard GeoTIFF rasters generated by external GIS tooling (GDAL, QGIS, ArcGIS, Google Earth Engine) using:
1. **ModelPixelScaleTag (33550) + ModelTiepointTag (33922):** The standard north-up georeferencing format where `pixel_scale = (scale_x, scale_y)` and `tiepoint = (i, j, k, x, y, z)`.
2. **ModelTransformationTag (34264):** A 16-element 4x4 affine matrix used by advanced GIS exporters. The engine extracts origin coordinates, checks for off-diagonal rotation elements, and computes cell resolution.
3. **GeoKeyDirectoryTag (34735) & GeoAsciiParamsTag (34737):** Parses projected and geographic coordinate reference systems (e.g., EPSG:32643, EPSG:4326).
4. **GDAL_NODATA (42113):** String-encoded nodata values parsed into proper numeric types matching raster data dtypes (`int16`, `uint16`, `float32`).

### Explicit Error Handling for Unsupported Files
- **Rotated Rasters:** If an affine transform contains non-zero shear/rotation terms ($a_{0,1} \neq 0$ or $a_{1,0} \neq 0$), the engine returns `status="ROTATED_TRANSFORM"` with an informative validation message.
- **Zero or Negative Pixel Scale:** Returns `status="INVALID_RESOLUTION"`.
- **Missing Georeferencing:** Rasters without tiepoints or transformation matrices return `status="MISSING_METADATA"`.
- **Missing CRS:** Rasters with valid geometry but unstated CRS return `status="MISSING_CRS"`.
- **Multi-Band Input to Single-Band Processors:** Returns `status="INVALID_DIMENSIONS"` if a multi-band image is uploaded to single-band terrain endpoints.
- **Undersized Rasters:** DEMs smaller than 2x2 pixels return an error because central-difference spatial gradients cannot be computed.

### Dependency Limitations & Architecture Choice
- **Windows Application Control Policy:** Native C-binary wheels for `rasterio` and `pyproj` are blocked by host OS policy.
- **Pure-Python & Resilient Stack:** TerraShield AI uses `tifffile` (for TIFF I/O and tag extraction), `shapely` (for vector geometry and spatial intersections), `scipy` (for spatial gradients), `matplotlib` (for headless image previews), and `utm` + `geographiclib` (for coordinate scaling). This completely eliminates dependency on blocked native DLLs.

## 5. Sentinel-2 Input Format & Workflow

### Supported Sentinel-2 Products
- **Product Type:** Sentinel-2 Level-2A (Bottom-of-Atmosphere surface reflectance).
- **Required Bands:**
  - **Band 4 (Red):** 665 nm central wavelength, 10m native spatial resolution.
  - **Band 8 (NIR):** 842 nm central wavelength, 10m native spatial resolution.
- **File Format:** Single-band 2D GeoTIFF.
- **Data Types:** Unsigned 16-bit integer Digital Numbers (`uint16`, 0–10,000 DN) or scaled floating-point reflectances (`float32`, 0.0–1.0).
- **Grid Requirements:** Both Red and NIR rasters must share identical spatial dimensions, coordinate reference systems, and spatial extents.

## 6. 5-Phase Project Roadmap

1. **Phase 1: Foundation & Working Prototype (Complete)**
   - Decoupled FastAPI backend and Streamlit frontend.
   - Deterministic 5-parcel sample watershed dataset.
   - Robust $L = \Delta R / N$ formula evaluation with zero-division handling.
   - Preserved and explicit exclusion reasoning.
2. **Phase 2: Geospatial Data Engine (Complete & Hardened)**
   - Ingestion and metadata validation of Digital Elevation Models (GeoTIFF).
   - Real gradient-based slope calculation in degrees (with geodesic latitude scaling).
   - Terrain aspect calculation as azimuth degrees from North ($0^\circ-360^\circ$).
   - Sentinel-2 Red and NIR band ingestion and NDVI computation.
   - SoilGrids metadata validation and vector protected-area intersection checks.
   - Secure artifact downloads and visual preview generation.
   - Multi-tag metadata support (33550/33922 and 34264) and rotated raster rejection.
3. **Phase 3: Geotechnical Intelligence Engine (Next Phase)**
   - Infinite slope stability equation solving for Factor of Safety ($FS$).
   - Wu-Waldron root-cohesion model ($\Delta C$) integration.
   - Surface temperature raster integration for urban-heat island mitigation.
4. **Phase 4: Spatial Recommendation Engine**
   - Live multi-spectral Copernicus Sentinel-2 NDVI time-series monitoring.
   - ISRIC SoilGrids spatial raster sampling.
   - Official World Database on Protected Areas (WDPA) vector exclusion masking.
5. **Phase 5: Multi-Criteria Optimization, Validation & Production Release**
   - Pareto multi-objective optimization across risk reduction, planting cost, and biodiversity.
   - Cloud containerization, automated testing, and production deployment.

## 7. Remaining Real-Data Verification Requirements (Pending External Data)

While the geospatial data engine has been verified with 62 passing automated tests, real-world field verification remains pending the acquisition of genuine external datasets for the Western Ghats corridor:
1. **SRTM 1-Arc-Second (30m) Elevation Tile (e.g., `n10_e076_1arc_v3.tif`):** Verification of actual terrain gradients against ground-truth survey contours.
2. **Sentinel-2 L2A BOA Surface Reflectance Bands (`B04_10m.jp2` -> GeoTIFF, `B08_10m.jp2` -> GeoTIFF):** Verification of canopy vegetation vigor in the Wayanad/Idukki escarpment.
3. **ISRIC SoilGrids 250m V2.0 (`clay_0-5cm_mean.tif`, etc.):** Verification of bulk density and clay content across Western Ghats lateritic soils.
4. **Protected Planet / WDPA Reserve Polygons (`WDPA_India_WesternGhats.geojson`):** Spatial boundary tests against Silent Valley and Periyar Tiger Reserves.
